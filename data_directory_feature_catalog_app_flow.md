### B3. Aspects-Only Variants
Drop from each: price, avg_rating, rating_count_log, review_velocity (+ install_count_log, days_since_update for apps). Everything else identical. Purpose: honest measure of LLM-feature contribution, free of label leakage via rating/volume.

### B4. Labels (targets)

| Field | Physical | App |
|---|---|---|
| success_score [0-100] | 0.40·volume_norm + 0.35·rating_norm + 0.25·velocity_norm | 0.30·install_norm + 0.30·rating_norm + 0.20·velocity_norm + 0.20·retention_norm |
| retention_proxy | — | clip(rating_count / install_count, 0, 1) |
| Normalization | min-max within category; log1p first on volume/installs | same |
| Exclusions | suspect_reviews=true products (burst / extreme-J / duplicate heuristics) | same |

### B5. Bridged Features (inference-time construction)
| Feature group | Source at inference |
|---|---|
| 9/11 aspect scores | Bridging LLM (all non-null, with reasoning) |
| price | user input |
| mention_rates | category means (from profile) |
| rating_count_log, velocity, install_count_log, days_since_update | category medians (neutral priors) |
| category | user selection |

# PART C — APP FLOW DOCUMENT

### C1. Application Map (Streamlit multipage)

```
Home ──► Prototype Simulator (default)
     ──► Category Explorer
     ──► Product Analyzer
     ──► About the Model
```

### C2. Flow 1 — Prototype Simulator (primary flow)

1. **Select category** — 10 tiles grouped Physical / Apps. Selection routes product_type and loads that category's profile summary in a sidebar ("what this market cares about": top-3 priorities, top pain point, median price).
2. **Enter specs** — structured form adapts to category:
   - Common: name (optional), price (required, numeric)
   - Physical examples: build material (select), battery hours, key features (multiselect + free text)
   - App examples: monetization (select), has_ads (toggle), key features, description (free text ≤100 words)
   - Validation inline: price > 0 required to enable Analyze
3. **Analyze (loading state ~5-15s)** — steps shown: "Consulting category intelligence… estimating consumer perception… scoring against 250 real products…"
4. **Results screen:**
   - Header: Viability gauge (full model %) + secondary "aspect-driven" % with an ⓘ explaining the difference
   - Bridged aspect radar/bars vs category average, each aspect expandable to show the LLM's one-line reasoning
   - Top 3 Risks (red) and Top 3 Strengths (green) from SHAP, each with impact value and plain-language line
   - Persistent disclaimer banner: "Estimate of consumer reception vs category norms based on public review data — not a sales forecast."
   - Actions: "Adjust specs" (returns to form with values retained) · "Explore this category"
5. **Iteration loop** — user tweaks a spec (e.g., metal build) and re-runs; delta chips show change vs previous run (viability +6.2, build_quality +2.1). This loop is the demo's money shot.

### C3. Flow 2 — Category Explorer
1. Pick category → profile page: price distribution, average aspect bars with mention-rate opacity, Top pain points / strengths cards with 3 real evidence quotes each, success-score histogram with p75 "success threshold" marker
2. White-space panel: lowest mention-rate aspects — "rarely discussed in this category"
3. CTA: "Simulate a product in this category" → Flow 1 pre-filled

### C4. Flow 3 — Product Analyzer
1. Category → searchable product dropdown (training set)
2. Product page: its aspect scores vs category average (diverging bars), success-score components breakdown, sampled evidence phrases
3. CTA: "Use as baseline in Simulator" → Flow 1 pre-filled with inferred specs

### C5. Flow 4 — About the Model
Static page rendering training_report.json + benchmark table: metrics per model (full & aspects-only), per-category R², LLM benchmark (agreement/latency/validity), data counts, limitations (proxy label, US-source gap for physical, robustness heuristics), citation block.

### C6. Error & Empty States
| State | UX |
|---|---|
| Bridging LLM failure after retries | "Couldn't reach the analysis model — try again" + retry button; never a stack trace |
| Category profile missing | Category tile disabled with tooltip "insufficient data" |
| Prediction > 25s | Timeout message + retry; log to Supabase |
| Free-text specs empty | Allowed — form fields alone suffice; description improves bridging |
